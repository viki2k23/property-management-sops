# Task Delegation and Follow-Up Framework

**Document type:** Framework & Templates
**Category:** Remote Team & Task Coordination
**Applies to:** Operations managers, team leads, property management
coordinators, and virtual assistants managing delegated work
**Last updated:** May 2026
**Author:** Vicky | Property Management Operations

---

## Purpose

This framework defines how tasks are assigned, tracked, followed up on,
and closed in a remote operations environment. Poor delegation is the
single biggest source of dropped tasks, missed deadlines, and team
friction in remote work.

This document eliminates the three most common delegation failures:

- Tasks assigned without enough context to execute
- No follow-up system — tasks disappear after assignment
- No clear definition of "done" — tasks linger in limbo

Every task delegated using this framework has a clear owner, clear
scope, clear deadline, and a built-in follow-up trigger.

---

## Scope

Applies to all task delegation within remote property management
operations and business support functions, including:

- Maintenance coordination tasks
- Tenant communication assignments
- Vendor follow-up tasks
- Leasing and administrative work
- Reporting and documentation tasks
- Any recurring or one-time operational assignment

## Definitions

| Term | Definition |
|---|---|
| **Delegator** | The person assigning the task — team lead, manager, or client |
| **Task Owner** | The person responsible for completing the task end to end |
| **Scope** | The specific boundaries of what is and is not included in the task |
| **Deadline** | The confirmed date and time by which the task must be completed |
| **Acceptance criteria** | The specific conditions that define when a task is considered done |
| **Follow-up trigger** | A scheduled checkpoint to verify task progress before the deadline |
| **Handoff** | The transfer of task ownership from one person to another |

## The Delegation Standard — 7 Elements

Every task delegation must include all 7 elements below. A task missing
any element is incomplete and must not be accepted as assigned.

### Element 1 — Task name
A clear, specific title. Not "handle the tenant issue" but "Send Stage 2
rent follow-up to tenant at Unit 4B — [Address]."

### Element 2 — Context
Why this task exists and what happened before. The task owner should
never have to ask "what is this about?" after reading the delegation.

### Element 3 — Specific actions required
Exactly what needs to be done, in what order. If there are decisions to
make, specify who makes them or what criteria to use.

### Element 4 — Deadline
Exact date and time — not "ASAP" or "when you get a chance." If
urgency is genuine, state the deadline and the reason.

### Element 5 — Acceptance criteria
What does "done" look like? Examples:
- "Tenant has confirmed receipt of the notice via text or email"
- "Work order is updated to Closed status with vendor invoice attached"
- "Owner has received the report and replied with acknowledgment"

### Element 6 — Resources and access
Every file, login, link, template, or piece of information the task
owner needs to complete the task without coming back to ask.

### Element 7 — Escalation path
Who to contact if a blocker appears, a decision is needed, or the
deadline is at risk.

## Task Delegation Templates

### Template 1 — Standard Task Delegation (Email or Slack)

> **Task:** [Specific task name]
>
> **Context:**
> [What this is about, what happened before, why it needs to be done now]
>
> **Actions required:**
> 1. [Step 1]
> 2. [Step 2]
> 3. [Step 3]
>
> **Deadline:** [Date] at [Time] [Timezone]
>
> **Done when:**
> [Specific acceptance criteria — what completion looks like]
>
> **Resources:**
> - [Link / file / login / template]
> - [Any additional access needed]
>
> **If blocked or deadline at risk:**
> Contact [Name] at [Contact method] immediately — do not wait until
> the deadline to flag.
>
> Please confirm you have received this and are able to complete it
> by the deadline.
>
> [Delegator name]

---

### Template 2 — Urgent Task Delegation (Same-day deadline)

> URGENT — [Task name] — Due by [Time today]
>
> **What needs to happen:**
> [Clear, specific action in 2–3 sentences maximum]
>
> **Deadline:** Today by [Time] — [reason for urgency]
>
> **Done when:** [One-line acceptance criteria]
>
> **Resources:** [Link or attachment]
>
> **Questions:** Call or text [Name] at [Number] — do not email for this.
>
> Please confirm receipt immediately.

---

### Template 3 — Recurring Task Delegation

Use when assigning a task that repeats on a schedule.

> **Recurring task:** [Task name]
> **Frequency:** [Daily / Weekly / Monthly / Other]
> **Schedule:** [Every Monday at 9am / 1st of each month / etc.]
> **First due:** [Date]
>
> **What to do each time:**
> 1. [Step 1]
> 2. [Step 2]
> 3. [Step 3]
>
> **Done when:** [Acceptance criteria per occurrence]
>
> **Where to log completion:** [Task system / shared sheet / email]
>
> **Exceptions:** [What to do if the scheduled time falls on a holiday
> or if the task cannot be completed as scheduled]
>
> **Questions about this recurring task:** Contact [Name]
>
> This task is now yours until further notice. If anything changes that
> affects your ability to complete it on schedule, notify me at least
> 24 hours in advance.

---

### Template 4 — Task Handoff (Transferring ownership)

Use when a task changes hands mid-completion.

> **Task handoff — [Task name]**
>
> **Handing off from:** [Name]
> **Handing off to:** [Name]
> **Reason for handoff:** [Brief explanation]
>
> **Current status:**
> [What has been done so far — be specific]
>
> **What still needs to be done:**
> 1. [Remaining step 1]
> 2. [Remaining step 2]
>
> **Deadline:** [Date and time — unchanged]
>
> **Known blockers or risks:**
> [Anything the new owner needs to watch out for]
>
> **Files and access:**
> [Everything the new owner needs]
>
> **Original delegator:** [Name and contact]
>
> New owner — please confirm you have reviewed this handoff and are
> able to complete the remaining steps by the deadline.

## Follow-Up System

Delegating a task without a follow-up plan is not delegation — it is
hoping. Every task needs a built-in follow-up trigger before the
deadline, not at it.

### Follow-up timing by deadline length

| Task deadline | Follow-up trigger |
|---|---|
| Same day (under 8 hours) | Check in at the halfway point |
| 24 hours | Check in at the 16-hour mark |
| 2–3 days | Check in at the 24-hour mark |
| 1 week | Check in at day 3 and day 6 |
| Recurring tasks | Check in after the first 3 occurrences, then monthly |

### Follow-up message templates

**Standard progress check:**

> Hi [Name], checking in on [Task name] — due [deadline].
> Quick status update:
> - On track / at risk / blocked?
> - Any issues I should know about?
> - Still expecting completion by [deadline]?
>
> Let me know and flag immediately if anything needs attention.
> [Your name]

**At-risk deadline follow-up:**

> Hi [Name], [Task name] is due in [X hours].
> I have not received an update — please confirm status now.
> If the deadline is at risk, we need to discuss immediately.
> Call or message me at [contact] right away.
> [Your name]

**Missed deadline follow-up:**

> Hi [Name], [Task name] was due at [time] and has not been marked
> complete. Please update me on the following immediately:
>
> 1. Current status of the task
> 2. What caused the delay
> 3. Revised completion time
>
> This needs to be resolved before end of shift today.
> [Your name]

## Task Acceptance Protocol

When a task is delegated to you, never silently accept. Always confirm
using this format within 15 minutes of receiving the assignment:

**Task acceptance confirmation:**

> Received — [Task name].
>
> Confirming:
> - I understand what needs to be done
> - Deadline: [Repeat the deadline back]
> - Done when: [Repeat the acceptance criteria]
>
> [If anything is unclear:]
> One question before I start: [Specific question]
>
> Will update you at [follow-up checkpoint] and flag immediately
> if anything blocks progress.
>
> [Your name]

> **Why this matters:** Confirming a task in writing protects you as the
> task owner. If scope or deadline changes later, your confirmation
> message is the baseline record of what was originally agreed.

## Task Tracking Log

Maintain a shared task log updated in real time. Every delegated task
must have a row. Never track tasks only in memory or chat messages.

| Task ID | Task Name | Delegated to | Delegated by | Date assigned | Deadline | Status | Follow-up date | Completion date | Notes |
|---|---|---|---|---|---|---|---|---|---|
| 001 | | | | | | | | | |
| 002 | | | | | | | | | |
| 003 | | | | | | | | | |

**Status options:** Not Started · In Progress · Pending · Blocked ·
Completed · Closed

> Update task status in real time — not at end of day. A stale task
> log is worse than no task log because it creates false confidence.

## Common Delegation Failures and How to Avoid Them

| Failure | Why it happens | How to prevent it |
|---|---|---|
| Task owner did not understand the scope | Delegator assumed context was obvious | Always write context explicitly — never assume |
| Deadline missed with no warning | No follow-up system in place | Set follow-up triggers at delegation time |
| Task completed wrong | Acceptance criteria were vague | Define "done" specifically before assigning |
| Task owner blocked but did not escalate | No escalation path given | Include escalation contact in every delegation |
| Task fell through the cracks | Tracked only in chat, not in a task log | Log every task in the shared tracker immediately |
| Scope crept beyond original assignment | New requests added without reconfirming deadline | Treat scope changes as new delegations — reset deadline |
| Handoff failed | Incomplete status update at transfer | Use the handoff template — never do verbal-only handoffs |

## Delegation Quality Checklist

Before sending any task delegation, check every item:

- [ ] Task name is specific — not vague or generic
- [ ] Context explains what happened before and why this matters
- [ ] Actions are numbered and sequential — not a paragraph of text
- [ ] Deadline is a specific date and time — not "ASAP"
- [ ] Acceptance criteria define exactly what done looks like
- [ ] All resources and access are included — task owner can start immediately
- [ ] Escalation path is named — a specific person, not "let me know"
- [ ] Follow-up trigger is scheduled in your calendar
- [ ] Task is logged in the shared task tracker

If any item is unchecked — fix it before sending.
